# Single-Company Commerce Refactor

This build refactors the storefront, administration app, and ASP.NET Core API into a **single-company commerce system**. Runtime workspace selection, tenant headers, custom-domain resolution, storefront keys, platform administration, subscription plans, and plan-based feature limits are no longer part of request handling or the user interface.

## What changed

### Single-company architecture

- The application always operates against company compatibility row `1`.
- The Web app loads branding and currency from `GET /api/company/public-profile`.
- The Admin app no longer asks for a company slug and no longer sends tenant/workspace headers.
- Old portal routes, tenant-management pages, platform settings, subscription-plan pages, and tenant-report pages were removed.
- JWTs contain user, role, permission, and optional branch claims only. They do not contain tenant, portal, platform-admin, or subscription claims.
- Old additional company rows are disabled during startup, not deleted, so historical data remains recoverable.

### Compatibility note

The existing database uses `TenantId`, `Tenants`, and `TenantSettings` names throughout the schema. Those **legacy storage names are intentionally retained** and fixed to company ID `1` to avoid a destructive database rewrite. They are no longer used for portal routing or company switching.

## Financial intelligence

The new `/api/admin/reports` module provides:

- Daily, current-week, current-month, current-year, and custom date ranges.
- Branch, currency, source, status, search, amount, sort, and pagination filters.
- Online revenue and manual-sales revenue.
- Cost of goods sold from cost snapshots recorded on every sold line.
- Gross profit, gross margin, operating expenses, payroll obligation, net profit/loss, and net margin.
- Cash received, cash paid, net cash flow, receivables, supplier payables, and payroll payables.
- Cash-flow and profit trends.
- Top-selling products.
- Transaction-level company ledger rows.
- Excel and PDF exports generated by the backend.

### Profit formulas

```text
Revenue = online order revenue + manual-sale revenue
Cost of goods sold = sum(sold quantity × cost captured when sold)
Gross profit = revenue − cost of goods sold
Net profit/loss = gross profit − expenses − payroll obligation
Net cash flow = customer payments − purchase payments − payroll payments − expenses
```

Cost snapshots were added to `OrderItems.UnitCost` and `InventorySaleItems.UnitCost`. This prevents a historical profit report from changing when product costs change later.

## Company worth

`GET /api/admin/reports/company-worth` calculates an operational worth estimate as of a selected date:

```text
Assets = calculated cash position + inventory at cost + customer receivables
Liabilities = supplier payables + payroll payables
Net worth = assets − liabilities
```

It also returns profit/loss for the selected comparison period.

This is an **operational estimate**, not a statutory balance sheet. The current domain does not record opening capital, external bank balances, loans, taxes payable, fixed assets, depreciation, or owner drawings. Add dedicated accounts and journal-entry tables before treating this value as formal accounting output.

## Customer ledger

Each customer profile now includes a ledger with:

- Opening balance before the selected range.
- Invoice debits from online and manual sales.
- Payment credits.
- Running balance and closing balance.
- Range revenue, cost of goods sold, and gross profit.
- Excel and PDF export.

Routes:

```text
GET /api/admin/reports/customers/{customerId}/ledger
GET /api/admin/reports/customers/{customerId}/ledger/export/excel
GET /api/admin/reports/customers/{customerId}/ledger/export/pdf
```

## Receipts

Order details, customer order history, and manual sales now provide:

- Print/preview A4 PDF.
- Downloadable A4 PDF.
- Downloadable continuous 80 mm thermal PDF.
- Downloadable PNG receipt image.

Receipt files include company details, branch, receipt reference, date, customer contact details, item lines, totals, payment state, remaining balance, notes, and company contact information.

Routes:

```text
GET /api/admin/receipts/orders/{id}/pdf
GET /api/admin/receipts/orders/{id}/image
GET /api/admin/receipts/manual-sales/{id}/pdf
GET /api/admin/receipts/manual-sales/{id}/image
```

These endpoints enforce the matching order or manual-sale view permission.

## Excel and PDF stack

- Excel generation: `ClosedXML`.
- PDF and PNG receipt/report generation: `QuestPDF`.
- `QuestPDF.Settings.License` is configured as `Community` in `Program.cs`.

Review QuestPDF's current Community License eligibility before production deployment. If the company is not eligible, change the configured license type and obtain the appropriate license.

The cost migration backfills historical sold-item costs using the most recent eligible purchase cost available before the sale. Review legacy sales that still receive a zero cost because no purchase history was available.

## Deployment

1. Back up the SQL Server database.
2. Confirm the company to keep uses compatibility row ID `1`.
3. Configure `ConnectionStrings:DefaultConnection`, JWT settings, CORS origins, and optional seed-admin credentials.
4. Restore and migrate the backend:

```bash
cd backend
dotnet restore
dotnet ef database update
dotnet run
```

5. Build Admin:

```bash
cd frontend/admin
npm ci
npm run build
```

6. Build Web:

```bash
cd frontend/web
npm ci
npm run build
```

7. Verify company profile, currency, colors, fonts, branches, permissions, historical cost snapshots, report totals, customer balances, and receipt output against known accounting records before going live.
